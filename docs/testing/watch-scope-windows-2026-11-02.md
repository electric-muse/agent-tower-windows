# 指定会话纳管与 Windows 运行检查

- 本机重启后无塔台进程，健康快照停在重启前；Windows 未注册塔台计划任务。旧快照中的 WebSocket 状态不能作为当前在线证据。
- `auto_watch=0` 只关闭自动建话题。原播报器仍将其它活跃会话发到主群，且观察话题映射为空。
- 增加可选 `watched_only=1`，仅播报手动纳管会话及塔台创建任务；当前本机实例已启用，`auto_watch` 保持关闭。未选中来源仍推进游标，不会在后来纳管时补发旧内容。
- 持久消息入队时唤醒发送线程，减少等待下一轮一秒轮询；API 限速与失败重试规则保持原样。
- 手动纳管遇到同群已有桌面接管话题时，核对根消息有效后复用该话题，避免重复建舱。
- Windows 登录自启经用户单独授权后已注册为 `AgentTower` 计划任务，当前状态为 Ready，触发器为当前用户登录。脚本使用基础 Python 与虚拟环境依赖，拒绝覆盖同名任务；注册时未启动第二个塔台进程。
- 离线验证：管理、话题交互、桌面控制和投递的相关 64 项测试通过。Windows 专用运行器 `-SelfTest`、计划任务 `-WhatIf` 均通过。
- 实机验证：两条指定 Codex 会话的根消息 API 回读成功，映射数为 2；塔台进程、飞书长连接、扫描、投递和命令线程健康。新进程启动后观察到 2 条新播报进入指定话题，主群新增播报为 0；入队到确认约 1.2 秒。未通过改写用户会话日志造测试事件。
