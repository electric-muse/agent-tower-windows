# 飞书图片投递验证

- 变更前，图片 Markdown 会转为路径文字；上传探针返回 `99991672`，确认缺少 `im:resource:upload`。
- 用户开通权限后，同一探针上传成功并返回图片键。塔台新增本机图片筛选、上传和话题内图片消息投递；正文卡片仍保留，图片作为独立消息送达。
- 只接收 Codex 回复显式引用的 PNG/JPEG/GIF、会话工作目录内且不超过 10 MB 的文件；每条回复最多 4 张。投递时重新核对文件指纹，防止排队后文件被替换。
- 普通纳管播报和飞书接管的桌面回复都进入持久投递队列，以事件身份去重。上传失败的图片保留在 `#deliveries`，不妨碍文字卡片送达。
- 实机验证：向“示例图片任务”话题发送标有 `AGENT TOWER IMAGE TEST` 的测试图，飞书根消息回复成功，消息 API 回读 `msg_type=image`。
- 重启后验证：`AgentTower` 计划任务处于 Running，飞书长连接、扫描、投递及命令线程健康；将标有 `QUEUE TEST` 的图片按已纳管会话身份入持久队列，实际发送状态为 `sent`，飞书回读仍为 `msg_type=image`。
- 离线验证：`test_media.py` 5 项、`test_desktop_control.py` 15 项、`test_management.py` 40 项和投递集成相关 3 项通过；Windows 运行器 `-SelfTest` 通过。`test_delivery_harness.IntegrationTests` 全类另有既有的 Windows 健康文案编码断言失败，图片及投递相关用例已单独通过。
- 手机端复核：群主聊天可见 `QUEUE TEST`，旧话题根卡创建于 10 月 28 日且较难定位。为“示例图片任务”建立新的观察话题并切换本机会话路由；用户进入完整话题后，截图确认独立图片消息和图片卡均正常显示。主聊天中的话题预览只露出前几条回复，不能据此判断图片投递失败。新根卡标题已按 Codex 本机目录修正。
